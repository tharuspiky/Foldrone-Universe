FOLDRONE / SECURITY

Security by
design.

Security is treated as a product requirement across the Foldrone ecosystem. Public web surfaces are delivered over HTTPS and are configured with defensive browser security headers, controlled resource policies and restrictive permissions where practical.

Web protection

Foldrone's public web properties use controls such as content-type protection, referrer policy, transport security, permissions policy, frame restrictions and content security policy. These controls are reviewed as the platform evolves.

Secrets and proprietary logic

Credentials, private keys and sensitive server-side values should never be embedded in browser-delivered source. Product implementations are structured so that secrets can remain outside public client code.

Responsible disclosure

If you believe you have identified a security issue affecting a Foldrone property, use the contact route on the Contact page and include the affected URL, a concise description and safe reproduction details. Do not include passwords, private keys or unrelated personal information.

This page is an overview of public security practices, not a guarantee that any system is immune from vulnerabilities.
